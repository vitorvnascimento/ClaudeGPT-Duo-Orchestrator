# v0.5.0

### English

- New opt-in executor `gemini` (Antigravity CLI `agy`, Google AI Pro subscription only). Disabled by default (`executors.gemini.enabled=false`); needs `billing.acknowledgeUnverifiableExtraUsage.gemini=true`. Executor only, never brain.
- Containment, two independent layers verified on macOS with the real `agy` 1.5.14 (the verified pair is `agy` 1.5.14 on darwin; any other version is refused until the battery passes on it; the browser tools are not exposed in headless mode and are documented as a limitation): a bridge `PreToolUse` gate hook (`.agents/hooks.json` in a disposable worktree) that allows only file reads inside the worktree and writes to the authorized targets, and fails closed; and a `sandbox-exec` profile that allows writes only to those targets, a private HOME and its TMPDIR (hard links, Apple Events and LaunchServices denied).
- Private HOME per chain (outside `.duo/`), linked only to `~/Library/Keychains`: the owner's `~/.gemini` config, plugins, MCP servers and instructions never load, and the owner's conversations are untouched. `duo gemini-state prune [--older-than <days>]` removes stale state.
- Inference-free login preflight (`agy models` with a fresh log): requires `authMethod=consumer` from the keyring. Google API-key/cloud variables in the brain environment block delegation.
- Gemini runs every kind in a worktree, never runs commands (acceptance stays with the bridge), is macOS-only, and is refused for any `agy` version/platform not in the verified list. Verified: `agy` 1.5.14 on macOS (real battery 13/14; the browser is not exposed to the model in headless mode, accepted as a documented limitation, and Q8 accepts that inconclusive result only with a complete stream and no browser step).
- Gemini containment hardening: protected dirs (`.agents`, `.git`, `.duo`, any case) are refused as targets and always denied by the OS profile; `grep_search` runs only on a single file (a directory search could reach denied files under equivalent spellings, so it is denied; `list_dir`/`find_by_name` still list names); deny rules match any Unicode form and case; each attempt has its own gate log; conflicting login signals are `unknown`; `agy models` failures are stored only as a failure class; prune validates the chain path (no links, project hash, owner) under the lock and ages chains by last use; availability checks the agy login and `sandbox-exec`; the catalog cache tracks the exact `agy --version`; any executor closing a chain removes its Gemini state.
- Quota/capacity fallback considers three accounts (same account first, then claude, codex, gemini), filtered by eligibility before ranking.
- `limits.maxConcurrentExecutors` keeps 4 as the recommended default but has no upper cap: any integer >= 1, or `null` for no limit. `duo doctor` warns above 4.

- Computer use (opt-in, macOS, Codex executor only): with `computerUse.enabled=true` and `needs: ["computer_use"]`, the Codex executor drives native apps through Codex's own `cua_repl`, with Codex's native per-app approval. Each request must list 1–20 `apps`; a fixed deny list (Mail, Messages, Passwords, Keychain Access, 1Password, Bitwarden, System Settings, terminals, Script Editor, Shortcuts, Automator, Console, Activity Monitor, Disk Utility, Claude, Codex/ChatGPT) is refused at admission whenever a request lists it. This is detection, not prevention: if the executor reaches an unlisted or denied app that Codex already approved, the action can happen before duo sees the audit event; duo then stops the executor and fails the task. The task runs in an exclusive slot (published as in-place so duo 0.4.0 also respects it); every action is audited from the stream and the native rollout (`.jsonl` and `.jsonl.zst`), the first violation stops the executor, and screenshots are kept only for calls the rollout attributes. A native permission denial blocks the task for `--resume` after approval; an interrupted computer-use task fails without resume. Ordinary tasks always run with the computer-use plugin disabled.
- Spawn hand-off: every executor slot moves reserved → spawning → running with the child PID, so a bridge crash between spawn and PID registration never frees the slot; recovery needs a confirmed process scan (`duo doctor --release-slot`). Unreadable slots keep blocking; malformed ones expire after 10 s under the admission lock, also from `apply` and `doctor`.
- Claude Code mod `codex-ativos` (in `mods/`, installable with `/plugin install codex-ativos --marketplace vitorvnascimento/ClaudeGPT-Duo-Orchestrator`): a band above the prompt with active subagents (openai-codex plugin jobs and duo slots) and how long each has run.
- Release gate on macOS (2026-11-22): real quality test **100/100** on `c882413`, real E2E battery **17/17**, real Gemini containment battery **13/14** (browser probe inconclusive: not exposed by headless `agy` 1.5.14) and offline suite with 0 failures. Evidence in [docs/evidencias/](evidencias/). Real E2E has not run on Windows; Linux remains untested.
- Known items for 0.5.1 (not regressions from 0.4.0): `duo doctor` runs executables configured in the project's `.duo/config.json` (treat project config as trusted, as in 0.4.0); a second `duo cancel` after a bridge crash can signal a reused PID; recovery relies on the registered launcher PID.

### Português

- Novo executor opcional `gemini` (Antigravity CLI `agy`, só pela assinatura Google AI Pro). Desligado por padrão; exige `billing.acknowledgeUnverifiableExtraUsage.gemini=true`. Só executor, nunca cérebro.
- Contenção com duas travas independentes verificadas no macOS com o `agy` 1.5.14 real (o par verificado é `agy` 1.5.14 no darwin; outra versão é recusada até a bateria passar nela; as ferramentas de navegador não são expostas no modo sem interface e ficam como limitação documentada): um hook `PreToolUse` do duo (`.agents/hooks.json` numa worktree descartável) que só libera leitura na worktree e escrita nos alvos autorizados, falhando fechado; e um perfil `sandbox-exec` que só libera escrita nesses alvos, num HOME privado e no TMPDIR dele (hard links, Apple Events e LaunchServices negados).
- HOME privado por cadeia (fora do `.duo/`), ligado só a `~/Library/Keychains`: config, plugins, MCPs e instruções do `~/.gemini` do dono nunca carregam, e as conversas dele ficam intactas. `duo gemini-state prune [--older-than <dias>]` limpa estados antigos.
- Verificação de login sem inferência (`agy models` com log zerado): exige `authMethod=consumer` pelo keyring. Variáveis de API/nuvem do Google no ambiente do cérebro bloqueiam a delegação.
- O gemini roda todo tipo de tarefa em worktree, nunca roda comandos (o aceite fica com a ponte), só no macOS, e é recusado para versão/plataforma do `agy` fora da lista verificada. Verificado: `agy` 1.5.14 no macOS (bateria real 13/14; o navegador não é exposto ao modelo no headless, limitação documentada e aceita, e o Q8 só aceita esse inconclusivo com stream completo e nenhum passo de navegador).
- Contenção do Gemini reforçada: pastas protegidas (`.agents`, `.git`, `.duo`, qualquer caixa) são recusadas como alvo e sempre negadas no perfil do SO; `grep_search` só roda sobre um arquivo (busca em pasta poderia alcançar arquivos negados por grafias equivalentes e é negada; `list_dir`/`find_by_name` seguem listando nomes); as regras de negação valem em qualquer forma Unicode e caixa; cada tentativa tem o próprio log do gate; sinais de login conflitantes viram `unknown`; falha do `agy models` é gravada só como classe; o prune valida o caminho da cadeia (sem link, hash do projeto, dono) com a trava e conta a idade pelo último uso; a disponibilidade confere o login do agy e o `sandbox-exec`; o cache do catálogo acompanha o `agy --version` exato; qualquer executor que encerre a cadeia apaga o estado do Gemini.
- O fallback de cota/capacidade considera três contas (a mesma primeiro, depois claude, codex, gemini), filtradas por elegibilidade antes da ordem.
- `limits.maxConcurrentExecutors` mantém 4 como padrão recomendado, mas sem teto: qualquer inteiro >= 1, ou `null` para sem limite. O `duo doctor` avisa acima de 4.
- Computer use (opcional, macOS, só executor Codex): com `computerUse.enabled=true` e `needs: ["computer_use"]`, o executor Codex usa apps nativos pelo `cua_repl` do próprio Codex, com a aprovação nativa por app do Codex. Cada pedido lista de 1 a 20 `apps`; uma lista fixa de apps negados (Mail, Mensagens, Senhas, Chaves, 1Password, Bitwarden, Ajustes do Sistema, terminais, Script Editor, Atalhos, Automator, Console, Monitor de Atividade, Utilitário de Disco, Claude, Codex/ChatGPT) é recusada na admissão sempre que um pedido a lista. Isso é detecção, não prevenção: se o executor chegar a um app fora da lista ou negado que o Codex já aprovou, a ação pode acontecer antes de o duo ver o evento de auditoria; o duo então para o executor e falha a tarefa. A tarefa roda em vaga exclusiva (publicada como in-place, para o duo 0.4.0 também respeitar); cada ação é auditada pelo stream e pelo rollout nativo (`.jsonl` e `.jsonl.zst`), a primeira violação para o executor e só ficam capturas de chamadas atribuídas no rollout. Negação nativa de permissão bloqueia a tarefa para `--resume` depois da aprovação; tarefa de computer use interrompida falha sem retomada. Tarefas comuns rodam sempre com o plugin de computer use desligado.
- Passagem para o spawn: toda vaga de executor vai de reserved → spawning → running com o PID do filho, então uma queda da ponte entre o spawn e o registro do PID nunca libera a vaga; a recuperação exige varredura de processos confirmada (`duo doctor --release-slot`). Slot ilegível continua bloqueando; malformado expira em 10 s sob o lock de admissão, também pelo `apply` e pelo `doctor`.
- Mod do Claude Code `codex-ativos` (em `mods/`, instalável com `/plugin install codex-ativos --marketplace vitorvnascimento/ClaudeGPT-Duo-Orchestrator`): faixa acima do prompt com os subagentes ativos (jobs do plugin openai-codex e vagas do duo) e há quanto tempo cada um roda.
- Gate da release no macOS (22/11/2026): teste de qualidade real **100/100** no `c882413`, bateria E2E real **17/17**, bateria real de contenção do Gemini **13/14** (sonda do navegador inconclusiva: não exposta pelo `agy` 1.5.14 sem interface) e suíte offline com 0 falhas. Evidências em [docs/evidencias/](evidencias/). A bateria E2E real não rodou no Windows; o Linux segue sem teste.
- Itens conhecidos para a 0.5.1 (não são regressões da 0.4.0): o `duo doctor` roda executáveis configurados no `.duo/config.json` do projeto (trate a config do projeto como confiável, como na 0.4.0); um segundo `duo cancel` após queda da ponte pode sinalizar um PID reaproveitado; a recuperação depende do PID do lançador registrado.
