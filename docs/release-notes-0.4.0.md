# v0.4.0

### English

- Up to four independent executors can run concurrently in separate worktrees per project (`limits.maxConcurrentExecutors`: 1..4, default 4). Parallel requests use `isolation: "worktree"`, distinct `taskKey` values and the same existing `runId`. Any in-place task remains exclusive; chain isolation is preserved across resumption and adaptive retries.
- The default budget is eight delegations per run, including retries and parallel dispatches. Quota and capacity updates are guarded; `duo status` shows active executor slots in text and JSON.
- Worktrees snapshot the brain's uncommitted tracked and untracked non-ignored changes, excluding denied paths and `.duo/`, within `maxSnapshotBytes`. Each executor's patch is verified against its own snapshot. Dependency links default to `["node_modules"]` and stay outside patches.
- `duo apply` integrates one successful patch at a time in the brain's chosen order. A changed HEAD or drift in files touched by the patch rejects integration; changes elsewhere in scope produce a warning. Rejected tasks must be rerun on the current base. Integration does not automatically merge or commit.
- Windows dependency directories use junctions, which do not require Developer Mode or administrator privileges. Recreating a file symlink without the required privileges blocks the snapshot with a clear diagnostic instead of silently omitting the link.
- Windows rename, removal and hard-link operations for locks, slots and the legacy mirror retry transient `EPERM`/`EACCES`/`EBUSY` failures for up to about two seconds. A failed rename never deletes its source.
- User-edited JSON accepts one leading UTF-8 BOM, including configuration, delegation/recommendation requests, package metadata, local schemas and Claude/MCP settings. Existing validation, errors, size limits and BOM characters inside values are preserved; JSONL/network protocols and generated state formats are unchanged.
- Codex provider tables qualify as official-equivalent only with literal `requires_openai_auth = true`, `wire_api` absent or `responses`, and `base_url` absent or exactly `https://api.openai.com/v1` or `https://chatgpt.com/backend-api/codex` (one optional trailing slash). Only known-safe metadata/transport keys qualify; credential, header, query, catalog-routing and unknown fields are rejected even when empty or explicitly null. Existing loopback authorization and root endpoint checks remain separate.
- `config/read` checks enabled configuration layers to distinguish implicit null/default fields from authored keys without retaining credential values. Missing or malformed evidence cannot hide unsafe fields; the TOML fallback keeps conservative layer/trust checks and rejects syntax it cannot verify.
- Dead-lock recovery uses a chain of permanent reclaim markers per dead generation, so at most one live recoverer can check and remove a dead guard; read errors never make a guard look abandoned. Tracked or staged symlinks are checked in the private worktree right after `git apply`; an unsafe link refuses the whole snapshot.
- Remaining risks are recorded in [docs/decisoes.md](decisoes.md): an older duo can reclaim a dead mirrored owner before the five-second refresh, with a longer window if the guard or event loop is busy. Exclusion assumes one PID namespace (no containers, WSL or synced folders shared between machines). Linked dependencies are shared, not copied: Codex keeps them outside writable roots, but writes through other means are not detected. Avoid mixing duo versions during parallel runs.
- Release gate on macOS (2026-11-07, commit `4c3274d`): real quality test **100/100**, real E2E battery **17/17** (including four real Codex executors at once), offline suite green; independent Claude and Codex adversarial reviews found no remaining blocker. Evidence in [docs/evidencias/](evidencias/). Windows offline suite passed on the earlier `acb91e4`; real E2E has not run on Windows, and Linux remains untested.

### Português

- Até quatro executores independentes podem rodar simultaneamente em worktrees separadas por projeto (`limits.maxConcurrentExecutors`: 1..4, padrão 4). Pedidos paralelos usam `isolation: "worktree"`, valores distintos de `taskKey` e o mesmo `runId` existente. Qualquer tarefa in-place continua exclusiva; o isolamento da cadeia é preservado em retomadas e retentativas adaptativas.
- O orçamento padrão é de oito delegações por run, incluindo retentativas e disparos paralelos. Atualizações de cota e capacidade usam guard; `duo status` mostra as vagas ocupadas pelos executores em texto e JSON.
- Worktrees capturam as alterações não commitadas rastreadas e não rastreadas não ignoradas do cérebro, sem caminhos negados nem `.duo/`, dentro de `maxSnapshotBytes`. O patch de cada executor é verificado contra seu próprio snapshot. Links de dependências têm padrão `["node_modules"]` e ficam fora dos patches.
- `duo apply` integra um patch bem-sucedido por vez, na ordem escolhida pelo cérebro. HEAD diferente ou deriva nos arquivos tocados pelo patch rejeita a integração; mudanças nos demais arquivos do escopo geram aviso. Tarefas rejeitadas precisam ser executadas novamente sobre a base atual. A integração não faz merge nem commit automático.
- No Windows, diretórios de dependências usam junctions, que não exigem modo desenvolvedor nem privilégios de administrador. Recriar um symlink de arquivo sem os privilégios necessários bloqueia o snapshot com diagnóstico claro, em vez de omitir o link em silêncio.
- No Windows, operações de rename, remoção e hard link de locks, vagas e espelho legado repetem falhas transitórias `EPERM`/`EACCES`/`EBUSY` por até cerca de dois segundos. Um rename que falha nunca apaga a origem.
- JSON editado pelo usuário aceita um BOM UTF-8 inicial, incluindo configuração, pedidos de delegação/recomendação, metadados de pacote, schemas locais e settings Claude/MCP. Validação, erros, limites de tamanho e caracteres BOM dentro dos valores são preservados; protocolos JSONL/de rede e formatos de estado gerado permanecem iguais.
- Tabelas de provedor Codex só qualificam como equivalentes ao oficial com `requires_openai_auth = true` literal, `wire_api` ausente ou `responses`, e `base_url` ausente ou exatamente `https://api.openai.com/v1` ou `https://chatgpt.com/backend-api/codex` (uma barra final opcional). Só qualificam chaves conhecidas de metadados/transporte; campos de credencial, cabeçalho, query, roteamento de catálogo e desconhecidos são recusados mesmo vazios ou explicitamente null. A autorização existente de loopback e as verificações de endpoints raiz continuam separadas.
- `config/read` confere as camadas habilitadas para distinguir campos null/default implícitos de chaves declaradas, sem reter valores de credenciais. Evidência ausente ou malformada não pode ocultar campos inseguros; o fallback TOML mantém verificações conservadoras de camadas/confiança e recusa sintaxe que não consegue verificar.
- A recuperação de lock morto usa uma cadeia de marcadores permanentes por geração morta, então no máximo um recuperador vivo confere e apaga o guard morto; erro de leitura nunca faz um guard parecer abandonado. Links simbólicos rastreados ou staged são conferidos na worktree privada logo após o `git apply`; link inseguro recusa o snapshot inteiro.
- Os riscos restantes estão registrados em [docs/decisoes.md](decisoes.md): um duo antigo pode recuperar o dono morto do espelho antes da renovação de cinco segundos, com janela maior se o guard ou event loop estiver ocupado. A exclusão supõe um único namespace de PIDs (sem contêiner, WSL ou pasta sincronizada entre máquinas). Dependências ligadas são compartilhadas, não copiadas: o Codex as mantém fora das raízes graváveis, mas escritas por outros meios não são detectadas. Evite misturar versões do duo durante runs paralelos.
- Gate da release no macOS (07/11/2026, commit `4c3274d`): teste de qualidade real **100/100**, bateria E2E real **17/17** (incluindo quatro executores Codex reais ao mesmo tempo), suíte offline verde; as revisões adversariais independentes do Claude e do Codex não deixaram bloqueio. Evidências em [docs/evidencias/](evidencias/). A suíte offline no Windows passou no `acb91e4` anterior; a bateria E2E real não rodou no Windows, e o Linux segue sem teste.
